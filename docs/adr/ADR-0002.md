# ADR 0002: PostgreSQL on Render

Date: 2026-07-05

## Status

Accepted

## Context

The project needs a relational database with strong integrity guarantees for time-tracking data, project management, and scheduling. Options evaluated include self-hosted PostgreSQL, managed cloud databases, and BaaS platforms.

## Decision

Use Render's managed PostgreSQL service. The Starter plan ($7/mo) provides 1GB RAM, 8GB storage, automated daily backups, and private network access from Render web services.

Justification:
- Co-located with the application services (also on Render) — low latency over private network
- Automated backups included
- No vendor lock-in — standard PostgreSQL, can export and migrate at any time
- Simple operational overhead — Render handles patching and uptime

## Consequences

### Positive
- Low operational overhead — no server management
- Private network access from other Render services
- Automated daily backups
- Standard PostgreSQL — no vendor-specific syntax
- Scales vertically — upgrade plan as needed

### Negative
- Fixed cost at $7/mo regardless of usage level
- No multi-region replication on Starter plan
- Storage capped at 8GB on the Starter plan (upgradeable)
- Not self-hosted — dependent on Render availability

## Alternatives Considered

- **Supabase (free tier):** Rejected — user prefers Render, free tier has usage limits and 7-day inactivity pause
- **DigitalOcean Managed DB:** Rejected — higher starting cost ($15/mo)
- **Self-hosted on VPS:** Rejected — additional operational overhead for a single developer
- **Railway:** Rejected — user specifically chose Render
- **Fly.io Postgres:** Rejected — user specifically chose Render
