# ADR 0003: PWA over Native Mobile App

Date: 2026-07-05

## Status

Accepted

## Context

Field technicians need a mobile interface for time tracking, viewing schedules, and submitting project updates from their iPhones while on job sites. The core workflows are form-heavy (clock in/out, notes, photos) rather than graphics-intensive or sensor-dependent.

## Decision

Build the field technician interface as a Progressive Web App (PWA) within the same Next.js application, rather than building a native iOS app with Swift/SwiftUI or a cross-platform framework like React Native or Flutter.

Key PWA features:
- "Add to Home Screen" install prompt on iPhone Safari
- Service worker for offline support (queue time entries)
- Web App Manifest with splash screen and theme colors
- Responsive design optimized for 390px viewport width
- Touch-optimized UI with large tap targets

## Consequences

### Positive
- Single codebase for office dashboard and mobile — shared components, types, API layer
- No App Store approval process — instant updates
- Significantly faster and cheaper to build than a native app
- Covers the core form-heavy workflows (time tracking, notes, schedule viewing)
- No platform-specific development skills needed

### Negative
- No access to hardware-level features (background sync, advanced push notifications)
- Limited offline storage compared to native (IndexedDB cap)
- Slightly less polished UX than a well-crafted native app
- iPhone Safari has some PWA limitations (push notification support lags behind Android)
- Cannot use NFC, Bluetooth, or other hardware features (not needed for v1)

## Alternatives Considered

- **React Native / Expo:** Rejected — overkill for form-heavy workflows, adds a second codebase to maintain, App Store deployment complexity
- **Flutter:** Rejected — same concerns as React Native, plus Dart language requirement
- **Native iOS (Swift):** Rejected — most expensive and time-consuming option
- **Capacitor (hybrid):** Considered but rejected — PWA covers current needs without native wrapper complexity
