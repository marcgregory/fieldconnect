# ADR 0001: Raw SQL with `pg` Driver (No ORM)

Date: 2026-07-05

## Status

Accepted

## Context

The project requires database access for a project management and time-tracking system. Modern Node.js ORMs (Prisma, Drizzle, Kysely) provide type safety and migration tooling but add an abstraction layer between the application and the database. The developer explicitly does not want an ORM and prefers full control over SQL queries.

## Decision

Use the raw `pg` PostgreSQL driver for all database access. Use `node-pg-migrate` for schema migrations. Write all queries by hand in SQL, organized by domain.

Key practices:
- Parameterized queries for all user input (SQL injection prevention)
- Domain-organized query files in `apps/api/src/db/queries/<domain>/`
- Migration files as plain SQL in `apps/api/src/db/migrations/`
- TypeScript types for query results defined in `@fieldconnect/shared`

## Consequences

### Positive
- Full control over query performance and optimization
- No ORM learning curve or magic behavior
- Direct use of PostgreSQL-specific features (CTEs, window functions, etc.)
- Simpler debugging — what you write is what the database runs

### Negative
- More boilerplate for CRUD operations compared to an ORM
- Manual type mapping between SQL results and TypeScript types
- Migration files must be handwritten SQL
- No automatic schema introspection or type generation

## Alternatives Considered

- **Prisma:** Rejected — ORM abstraction, auto-generated queries, user preference against it
- **Drizzle:** Rejected — closer to SQL but still an abstraction layer
- **Kysely:** Rejected — type-safe query builder, still an abstraction
- **Supabase JS client:** Rejected — ties to Supabase platform
